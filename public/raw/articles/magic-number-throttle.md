# Magic Number 治理

Magic number 不是“所有数字字面量”，而是**携带了隐藏决策、却没有表达语义和依据的字面量**。治理目标也不只是把 `30` 改名为 `MAX_ITEMS`：真正要解决的是谁决定了这个值、它约束什么、能否调整、何时失效，以及改变后如何验证。

## 判断原则

先问三个问题：

1. 读者不看上下文，能否知道这个值的含义和单位？
2. 这个值变化时，是否应该只改一个位置，还是随部署、任务或数据变化？
3. 这个值错了会怎样：只影响排版，还是静默丢数据、改变业务契约或触发级联故障？

只有“值具有非显然语义”时才需要治理。循环步长、集合空值、简单代数常数和显然的索引通常可内联；业务阈值、协议值、时间预算、容量参数、算法权重和截断上限通常不可。

经典重构方法建议用符号常量替代有特殊含义的字面量；ESLint 与 Ruff 的官方规则也都保留 allowlist、索引和默认值等例外。这两点共同说明：**目标是暴露决策，不是消灭字面量。** 一刀切会制造 `ONE = 1` 一类噪声，反而降低可读性。

## 值的五种归属

| 类型 | 例子 | 正确承载方式 |
|---|---|---|
| 标准或数学不变量 | HTTP 状态、协议位、单位换算 | 标准库常量、枚举或局部具名常量 |
| 产品/领域契约 | 分页上限、评分边界、保留期 | 领域常量或版本化契约；引用需求依据 |
| 部署配置 | 超时、连接池、外部配额、资源句柄 | 配置系统或环境变量；启动时校验 |
| 派生值 | 可用窗口减输出预留、批大小由预算计算 | 纯函数计算；不要重复保存结果 |
| 经验标定值 | 并发膝点、召回阈值、分块有效区 | 配置 + 决策记录 + 基准结果 + 重标定条件 |

兼容旧数据或旧协议的历史值属于第六类：**受控债务**。它可以保留，但必须写清兼容对象、退出条件和迁移方案，不能伪装成当前最佳实践。

The Twelve-Factor App 强调“会随部署变化的配置应与代码分离”。这不等于“所有常量都放环境变量”：数学不变量和稳定领域契约放入部署配置只会丢失类型与结构；反过来，把外部配额和资源规模编译进代码，也会让同一构建无法安全运行在不同环境。

## 治理流程

### 1. 先分类，不急着抽常量

确认它是协议、领域、部署、派生还是标定值。同一个数字在不同位置可能代表完全不同的决策，不能因为数值相同就合并成一个常量。

### 2. 用名字表达语义和单位

好名字说明“限制什么”，而不是复述数值：

```python
REQUEST_TIMEOUT_SECONDS = 30
MAX_RECORDS_PER_PAGE = 100
```

若单位容易混淆，名称必须带 `_MS`、`_SECONDS`、`_BYTES`、`_TOKENS` 等后缀。布尔边界优先封装成谓词；状态值优先用枚举；能从数据计算的值优先调用函数，不额外保存常量。

### 3. 放在最小正确作用域

- 只服务一个函数且稳定：函数附近的局部常量。
- 同一模块共享：模块级常量。
- 跨模块共享同一契约：领域 constants/schema 模块。
- 随部署变化：类型化配置层。
- 随任务或模型变化：任务级配置或能力表。

“集中到一个全局 numbers 文件”不是治理。它容易把同值不同义的数字错误耦合，并让修改影响范围不可见。

### 4. 绑定依据

值至少需要一种可追溯依据：

- RFC、IANA、语言或 SDK 标准；
- 产品/领域契约；
- 外部服务公开限制；
- 基准、压测、质量评测或真实数据分布；
- 历史兼容约束。

注释只写代码无法表达的约束，例如“为什么不能更大”“改变后要重跑什么”。不要写“最大重试次数为 3”这种重复变量名和值的注释。

### 5. 验证边界，而不是锁死实现

- 契约值：测边界两侧和版本兼容。
- 配置值：测非法值、单位、缺省值和启动失败。
- 派生值：测公式不变量和极端输入。
- 标定值：保存固定数据集、指标和重标定条件。
- 截断值：测输入覆盖率与 fail-aloud，不只测函数“成功返回”。

## LLM 预算是高风险子类

LLM 链路中的固定条数、字符数、token 数和 `max_tokens` 会造成“静默节流”：请求成功、JSON 合法，但模型从未看到完整输入，或输出在结构末尾被截断。

需要区分：

- **能力硬顶**：模型声明的 context window 与最大输出。
- **质量有效区**：当前模型 × 当前任务在真实评测上仍能可靠利用的范围。
- **输出预算**：按 schema 和列表硬顶的最坏情况估算。
- **装填策略**：在硬顶与有效区内按 tokenizer 装入内容。
- **超限策略**：分块、检索、层级归并或明确拒绝。

能力硬顶不等于质量有效区。论文 *Lost in the Middle* 表明，即使长上下文模型能够接收更长输入，中部信息利用率也可能下降。因此“窗口放得下”不能作为“整段一次喂入”的充分依据。

### 工程经验：长文本静默截断

**把截断数字改名，解决不了静默少喂。** 某长文本关系抽取曾固定最多若干块、每块只留固定前缀。短样本全过，长样本也返回合法 JSON，但大部分原文从未进模型，召回被结构性封顶。根因不是字面量没抽常量，而是：阈值没绑模型能力和数据上沿；截断没有 `fed/total/dropped`；测试只看结构成功；换模型后旧阈值仍当通用经验。正确做法是登记模型能力、tokenizer 装填、超有效区分块归并、记录覆盖率，并用长输入基准标定单块上限。

## 自动化边界

Lint 适合发现“可疑字面量”，不能证明值已经治理：

- ESLint `no-magic-numbers` 支持忽略索引、默认值、枚举和指定字面量。
- Ruff `PLR2004` 主要检查比较表达式中的未命名值，并默认忽略常见值。
- AST/快照规则可补充扫描 `[:N]`、`top_k=N`、`max_tokens=N` 等静默截断模式。

自动化规则应先 warning、再按高风险目录收敛，最后才进入 CI。Allowlist 必须最小化并说明原因；把配置目录或整个业务目录全部豁免，会让真正风险消失在盲区。

## 禁止模式

- 把所有数字搬到一个全局 constants 文件。
- 用 `MAX_VALUE`、`DEFAULT_LIMIT` 这类名字隐藏而不是表达语义。
- 只抽常量，不记录依据、单位、作用域和变更条件。
- 把会随部署变化的值编译进代码。
- 把稳定领域契约全部外置成无类型环境变量。
- 用 p50 或“常见情况够用”推导最坏情况输出预算。
- 从另一任务复制窗口、重叠率、并发或阈值。
- 截断输入但没有覆盖率、日志或降级状态。
- 为了消除 lint 告警创建无意义常量。

## Agent 执行规则

遇到可疑数字时默认：

1. 判断它是否携带隐藏决策，而不是机械抽取。
2. 分类为标准、领域、部署、派生、标定或兼容值。
3. 选择最小正确作用域，并在名称中表达语义和单位。
4. 绑定标准、契约、数据或实验依据；没有依据的标为待标定。
5. 为高风险边界补可观测性与行为验证。
6. 检查同值不同义和同义多处，避免错误合并或继续漂移。

评审至少回答：为什么是这个值、谁能改、作用于哪里、改变会影响什么、如何验证、何时需要重标定。
